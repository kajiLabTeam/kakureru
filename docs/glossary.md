# 用語集（ユビキタス言語）

kakureru で使う語彙。**コード上の型名・enum値・変数名はここの英語表記に揃える**。日本語と英語の対応が曖昧なまま実装を進めない。

| 言葉 | 英語 | 説明 |
| --- | --- | --- |
| ルーム | `ROOM` | ユーザーの集合 |
| ルーム設定 | `ROOM_SETTING` | ゲームエリア・鬼放出時間・ゲーム時間の設定 |
| ルームコード | `ROOM_CODE` | ルームに参加するための4桁の数字。**db上のルームのIDとは区別される** |
| ゲームエリア | `GAME_AREA` | ルーム設定の1つ。緯度経度の3以上の配列（ポリゴン・閉区間として見る） |
| ユーザー | `USER` | ルームに所属する人。**ルームをまたいだ関係は無い** |
| ホスト | `HOST` | ルームを作成した人 |
| 逃走者 | `FUGITIVE` | ユーザーの種別の一つ |
| 鬼 | `DEMON` | ユーザーの種別の一つ |
| 距離感 | `SENSE_OF_DISTANCE` | 互いの気圧の差・Wi-Fiの強度の取得と変化の共有 |
| ユーザーの情報 | `FUGITIVE_INFORMATION` | GPSの情報・距離感 |
| 新鬼 | `NEW_DEMON` | 鬼に捕まった逃走者 |

## 実装への影響

- **`USER` はルームスコープ**。ルームをまたいだ関係が無いので、アカウントの永続化は不要で、RTDBにもトップレベルの `users/` は置かない（`rooms/{roomId}/users/{uid}` のみ）。認証は匿名でよい。
- **`ROOM_CODE` と roomId は別物**。4桁コードは人が入力するためのもの、roomId はdb上の識別子。`docs/rtdb-schema.md` の `roomCodes/{code} → roomId` はこの区別を実現するための逆引き。両者を混同した変数名（`roomId` に4桁コードを入れる等）を作らない。
- **`GAME_AREA` は閉区間のポリゴン**。エリア内外の判定は点と多角形の内外判定（point-in-polygon）で行う。円や矩形で近似しない。

## 未確定

- **`FUGITIVE_INFORMATION` の名前が実態とずれている**。日本語は「ユーザーの情報」だが英語は「逃走者の情報」。シナリオ13では逃走者も鬼のGPSを見るので、鬼の情報もこの語に含まれるはず。`USER_INFORMATION` にするか、逃走者側だけを指す語として使い続けるかを決める必要がある。`docs/rtdb-schema.md` の `fugitiveInfoDelaySec` の意味もこれに引きずられて曖昧になっている
