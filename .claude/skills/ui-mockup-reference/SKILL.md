# UI Mockup Reference

このFlutterアプリ(kakureru)のUI・デザインを触るときは、**実装を始める前に** `docs/ui-mockup-2a.html` を必ず参照する。

## このモックが何か

「実装済みアプリ（kajiLabTeam/kakureru）のUI改修案」として作られた、実画面ベースの改修モック8画面。1つのHTMLファイルに8画面ぶんのモックアップが並んでおり、それぞれに設計意図を説明する「改善：」コメントが添えられている。

- ブラウザで直接開くか、Readツールでこのファイルを読んで内容を確認する
- スクリーンショットで見た目を確認したい場合は `run` スキル経由でブラウザ表示するか、`file://` パスで開く

現在(2026-08-30時点)収録されている8画面:

|---|---|---|
| 2a-01 | ホーム | 名前が空/超過ならボタン自体を無効化。4桁コードを1桁ずつのマスに分解 |
| 2a-02 | 待機（ホスト視点） | 開始条件を上部にチェックリスト化。キャリブレーションを説明つきの行に。行ごとに役割・状態を明記 |

このテーブルは概要把握用のキャッシュに過ぎない。実装の詳細（余白・角丸・フォントサイズ・具体的なdivの構造など）は毎回ファイル自体を読んで確認すること。ファイルは更新されうるため、このテーブルの内容を鵜呑みにしない。

## 使い方

1. 触ろうとしている画面に対応するモック(上表のID)がないか確認する。対応するモックがあれば、Readツールでそのセクション(`data-screen-label`属性で検索するとよい)を読み、レイアウト・配色・文言・状態表現を把握する
2. 現在の実装(該当する`lib/features/**/view/*.dart`)と見比べ、モックとの差分を洗い出す
3. **このモックは「改修案」であり確定仕様ではない**。差分が見つかっても、それが今回の依頼の範囲か、まだ合意されていない提案なのかをユーザーに確認してから実装する。特に「改善：」コメントに書かれた変更は、依頼と無関係なら勝手に一緒に実装しない(スコープ外の変更を混ぜない、というAGENTS.mdの一般方針にも合致する)
4. 対応するモックが無い画面(新規画面など)の場合は、既存モックの配色ルール・トーン(角丸・余白感・フォント)だけ踏襲し、その旨をユーザーに一言添える

## 注意

- これはあくまで見た目のデザイン参照であり、状態管理(hooks/Riverpod)やデータ構造(Freezed)の規約はAGENTS.mdに従う。デザイン整合と実装規約は別軸なので混同しない
- モックHTMLはあくまで静止画的なモックアップであり、実際のFlutterウィジェットツリーやアニメーション挙動までは規定していない。実装の細部は既存コードの慣習(既存widgetの構造・命名)を優先する
